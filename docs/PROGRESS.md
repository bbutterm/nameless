## Фаза 0 — Канон (закрыта)

**Сделано.** Агент-хранитель канона выработал три контрастных костяка мира и выбрал
один: город **Заклад**, где память материальна и служит валютой. Игрок — **Неоплатный**,
заложивший всю свою память оптом; смерть не может взять с него плату и каждый раз
возвращает его, выдав в неустойку один лот из его собственного архива.

**Почему так.** Из трёх вариантов этот единственный делает смерть *механически
осмысленной*, а не косметической: возврат лота — это буквально валютная операция мира,
а не сюжетная условность. Плюс он даёт естественный юмор (прейскуранты на невыразимое)
и трагедию из одного и того же материала.

**Артефакты.** `docs/CANON.md` (516 строк), `docs/CHARACTERS.md`, `docs/MORNING_REPORT.md`.

## Фаза 1 — Ядро (в работе)

### Итерация 1.1 — скелет монорепо и движок

**Сделано.** pnpm-workspaces, TypeScript strict (`noUncheckedIndexedAccess`,
`verbatimModuleSyntax`). Четыре пакета: `engine`, `content`, `client`, `sim`.

Движок (`packages/engine`), ноль зависимостей от UI:
- `rng.ts` — mulberry32 + FNV-хэш строк, снимок/восстановление состояния, `fork()`.
  Вся случайность игры идёт только отсюда, иначе симуляции бессмысленны.
- `types.ts` — контракт данных: условия, эффекты, сцены, юниты, способности,
  жизни, воспоминания, смерти, главы. Оси/флаги — свободные строки: движок про них
  ничего не знает, реестр живёт в контенте.
- `state.ts` — GameState + чистое применение эффектов.
- `conditions.ts` — вычисление условий и сбор ссылок (для валидатора).
- `dialogue.ts` — обход графа сцены, фильтрация вариантов, **железное правило ≥2**.
- `combat.ts` — строй против строя: два ряда, правило прикрытия переднего ряда,
  инициатива, кулдауны, статусы, щиты, намерения врагов, ИИ и автобой.
- `progression.ts` — опыт, эволюции, выбор закрепляемого воспоминания при смерти.
- `save.ts` — версионированные сейвы с цепочкой миграций.

**Почему так.** Разделение «движок ничего не знает про контент» — единственный
способ выполнить требование «добавление контента = добавление файла». Оси как
свободные строки позволили канону выбрать четвёртую ось (`grasp_release`) уже
после того, как движок был написан, — и ничего не пришлось трогать.

**Решение по локализации.** Тексты сцен двуязычные прямо в JSON
(`{ru, en}`), а не ключи во внешних словарях. Сцена остаётся самодостаточной
и читаемой, сценарист не ведёт параллельный файл переводов. Строки интерфейса —
отдельно, в `client/src/i18n.ts`.

**Чем проверено.** `pnpm --filter @nameless/engine typecheck` — зелено.

### Итерация 1.2 — пакет контента

**Сделано.** zod-схемы на весь контент; правила прямо в схеме ловят нарушения
мобильного UX: реплика выбора >10 слов и подпись на карте >8 слов — ошибка
валидации, а не пожелание. Валидатор ссылочной целостности (`validate.ts`):
битые переходы, дубликаты id, недостижимые узлы, сироты-флаги, два врага в одной
клетке, >15 пузырей подряд без выбора.

**Решение: генератор реестра вместо общего index-файла.** `gen-index.ts` сканирует
`data/**` и пишет `src/generated.ts`. Причина прозаическая: над контентом работают
несколько агентов параллельно, и любой общий index стал бы точкой конфликта.
Теперь «положил файл — он в игре».

**Чем проверено.** `pnpm --filter @nameless/content validate` работает end-to-end.

### Итерация 1.3 — клиент

**Сделано.** React + Vite, PWA (манифест, standalone, сервис-воркер cache-first,
сгенерированные без зависимостей иконки), портретная блокировка с плашкой,
тёмная тема, ru/en, вибрация с выключателем.

Экраны: титул, диалог (чат-лента с портретами, подсветкой ключевых слов и
раскрывашками «рассмотреть ближе»), бой (карточки в два ряда, намерения врагов,
всплывающие цифры, анимации движением самих карт), церемония смерти
(трёхфазная: пробуждение → лот → пробуждённая жизнь).

**Native-feel.** Отключены выделение текста, контекстное меню по долгому тапу,
синяя подсветка тапа, резиновый скролл и двойной тап-зум; safe-area insets;
тапабельные цели ≥48px; текст диалогов 17px.

**Арт-слоты.** `packages/content/assets/cards/<id юнита>.webp` автоматически
вытесняет процедурную заглушку — через `import.meta.glob`, без правок кода.

**Чем проверено.** `typecheck` зелёный, `vite build` — 32 КБ gzip приложения
плюс 45 КБ React.

### Итерация 1.4 — симуляторы

**Сделано.** `packages/sim`:
- зеркальный турнир юнитов (винрейты, коридор 42–58%);
- прогон сюжетных боёв ботом (коридор 60–85%);
- проверка детерминизма (два прогона одного сида дают идентичный лог);
- фаззер диалогов: 300 случайных «личностей» с перекосом в края осей, поиск
  тупиков (<2 вариантов **без** страховочного механизма движка), мёртвых
  вариантов, недостижимых узлов, зацикливаний, охвата реплик.

**Почему фаззер считает варианты без страховки.** Движок никогда не оставит
игрока с одной кнопкой — но если страховка сработала, значит сцена написана
неправильно. Симулятор обязан видеть исходную проблему, а не залатанную.
