# МЕХАНИКИ — «Безымянный»

> Технический документ. Канон главнее. Здесь только числа, формулы и правила,
> по которым числа выбраны. Всё соответствует коду в `packages/engine/src/` и
> данным в `packages/content/data/`; расхождение — баг документа.
> Выжимка (Ч3): история опытов и разовые замеры вырезаны — актуальные числа
> даёт `pnpm sim`.

Версия контента: **34 юнита, 30 способностей, 4 оси, 5 жизней, 15 воспоминаний**.

## 1. Оси личности

### 1.1. Диапазон и край

| Параметр | Значение | Где живёт |
|---|---|---|
| Диапазон | `[-100, +100]` | `AXIS_MIN`/`AXIS_MAX` в `state.ts` |
| Старт | `0` | `axes.json`, поле `start` |
| Край | `60` по модулю | `axes.json`, поле `extreme` |
| Клампинг | `clampAxis` округляет и обрезает | `state.ts` |

Четыре оси: `mercy_cruelty`, `honesty_deceit`, `reason_obsession`,
`grasp_release`. Числа игроку не показываются никогда — мир отвечает
поведением, ценами и составом отряда.

### 1.2. Величины сдвига

Три калибра эффекта `{ "kind": "axis", "axis": …, "delta": ±N }`:

| Калибр | delta | Что это в сцене | Выборов до края в одиночку |
|---|---|---|---|
| Мелкий | ±3 | тон реплики, мелкая уступка | **20** |
| Значимый | ±8 | поступок с последствием | **8** |
| Определяющий | ±15 | развилка узла | **4** |

Калибровка: глава — 3–5 вылазок, ~18 сдвигов; на ведущую ось
последовательного игрока ложится ~45 очков за главу. Отсюда: край на ведущей
оси — середина второй главы; случайно край не берётся (разнобойный игрок
держится в ±35); разворот от +60 до −60 = 8 определяющих выборов подряд.
Порог найма ±40 (раздел 6) берётся раньше края — к концу первой главы:
сначала приходят наёмники, потом мир реагирует крайностью.

## 2. Бой

Строй против строя: два ряда по три слота (`SLOTS_PER_ROW = 3`), до шести
юнитов на сторону. Всё ниже — ровно то, что делает
`packages/engine/src/combat.ts`.

### 2.1. Урон

```
raw       = atk_эфф · power
mitigated = raw · K / (K + def_эфф)          K = ARMOR_K = 50
variance  = U[0.88, 1.12]                    DAMAGE_VARIANCE = 0.12
crit      = 8 % → ×1.5
amount    = max(1, round(mitigated · variance · crit))
```

`atk_эфф`/`def_эфф` — базовые статы плюс бафы минус дебафы, снизу ноль
(`effectiveStat`). Свойства, на которые опирается баланс:

- **Броня не обнуляет урон**: при def 50 урон режется вдвое. Танк тянет
  время, а не отменяет бой.
- **Каждая единица брони дешевеет** (убывающая отдача `K/(K+def)`), поэтому
  в коридорах статов броня растёт медленнее hp. При реальных def 3–16
  множитель 0.76–0.94 — броня в этой системе не рычаг живучести, hp — рычаг.
- **Минимум 1** — безвредных ударов нет.
- Средний множитель крита = `1.04`, учитывается во всех расчётах.

### 2.2. Очередь хода

```
init_ключ = effectiveStat(u, 'initiative') + rng.float(0, 0.999)
order     = живые, по init_ключу по убыванию
```

Разрыв ничьих — сид прохождения: два прогона одного сида дают посимвольно
одинаковый лог (тест в `combat.test.ts`, `determinismCheck` в симуляторе).
Добавка < 1, поэтому разница в 1 очко инициативы не отыгрывается броском.

### 2.3. Правило строя

`legalTargets`: `enemy_front` видит только передний ряд врага, пока в нём
кто-то жив; опустевший передний открывает задний. Исключения: `enemy_any`
(достаёт задний сразу), `piercing: true`, `enemy_all`/`enemy_row` (площадь).

Задний ряд Братства Чистой Головы пуст нарочно (канон): все три юнита —
`row: "front"`, `enemy_any` против них тратится впустую.

### 2.4. Порядок раунда

1. `beginRound`: тикает `dot`, снимаются мёртвые, длительности статусов −1
   и истёкшие выбрасываются, кулдауны −1.
2. Пересчёт очереди по инициативе.
3. Намерения врагов (`rollIntents`) — игрок видит иконки.
4. Ходы по очереди; оглушённые/мёртвые пропускаются с записью `blocked`.
5. Конец очереди → шаг 1.

**Контентщику:** кулдаун уменьшается в начале раунда, поэтому `cooldown: 1`
— «каждый раунд»; реальный простой = `cooldown − 1` раундов.

### 2.5. Лимит раундов

`DEFAULT_TURN_LIMIT = 30`; раунд 30 закончился — **поражение**, не ничья
(состав, неспособный побеждать, не награждается). Внимание, ловушка:
`turnLimit: 0` в `BattleDef` означает немедленное поражение, а не «без
лимита» (TODO п.4) — ноль не писать.

### 2.6. Живучесть по рядам

По медианным статам ростера: **задний ряд умирает за 2–4 удара, передний —
за 4–6**. Разрыв в полтора-два раза — причина, по которой строй имеет смысл.
Расчётная длина боя отсюда — 6–9 раундов при полных составах.

## 3. Шесть ролей

Роль — не поле в данных, а связка «коридор статов + набор способностей».
В `traits` пишется метка (`shield`, `fighter`, `shooter`, `mage`, `healer`,
`breaker`) — для подсказок интерфейса и отбора в симуляторе.

### 3.1. Базовые коридоры по тирам

| Тир | hp | atk | def | initiative |
|---|---|---|---|---|
| 1 | 28–48 | 7–12 | 3–9 | 8–14 |
| 2 | 45–72 | 12–18 | 6–12 | 7–13 |
| 3 | 70–110 | 18–26 | 10–18 | 8–15 |

Передний ряд получает премию за живучесть (hp и def в верхней половине
коридора, задний — в нижней): он принимает весь ближний бой. Ряд, тир 1:
передний hp 38–48 / def 5–9, задний hp 28–34 / def 3–4.

Единственное исключение ростера — `posul` (тир 2, atk 7): мираж по канону
не наносит урона, он принимает удары и лопается. Любой другой юнит вне
коридора — баг данных.

### 3.2. Роли

| Роль | hp | atk | def | init | Типовой набор | Пример |
|---|---|---|---|---|---|---|
| **Щит** | верх | низ | верх | низ | самощит/щит-союзнику + слабая атака | `unclaimed_pledge`, `vault_lock` |
| **Боец** | середина-верх | верх | середина | середина | атака cd 0 + бурст cd 1–2 | `throat_taker`, `debt_bailiff` |
| **Стрелок** | низ | середина | низ | верх | `enemy_any` cd 0–1 | `hook_man`, `dusty_errand_boy` |
| **Маг** | низ-середина | верх | низ-середина | середина | площадь cd 3–4 + одиночная | `tar_burner`, `flask_hoarder` |
| **Лекарь** | середина | **середина** | середина | середина | лечение/снятие статусов + атака | `almshouse_sister`, `vodonos` |
| **Ломщик** | середина | середина | середина | верх | дебафы def/atk + атака | `svidetel`, `cold_reckoner` |

Два правила, которые легко нарушить:

1. **У лекаря atk не может быть низким**: лечение = `round(atk_эфф · power)`
   — масштабируется атакой носителя.
2. **У каждого юнита должна быть способность с `cooldown ≤ 1`** — иначе
   `planAction` возвращает `undefined` и юнит пасует (`blocked`).

## 4. Способности

30 штук, `packages/content/data/abilities/`: `melee.json`, `ranged.json`,
`support.json`, `curses.json`.

### 4.1. Кулдаун против силы

Потолок для одиночной цели по переднему ряду:

```
power_max(cd) = 1.1 + 0.4 · cd
```

Выведено из «урона за раунд»: `power / (cd + 1)` держится в 0.5–1.0 —
длинный кулдаун покупает всплеск, а не пропускную способность.

**Скидка за добавочный эффект:** способность, вешающая статус помимо урона,
теряет 0.2–0.4 силы против потолка; оглушение — дороже всего.

**Дебафы и лечение — `power: 0`**, их вес живёт в `effects`. Побочный
эффект: `planAction` сортирует по `power · (cd > 0 ? 1.25 : 1)`, поэтому
способность с `power: 0` бот выбирает последней; юнит с одними нулевыми
способностями в автобое бесполезен (см. 8.5).

### 4.2. Потолок площади

```
power_max(enemy_row) = 0.55 · power_max(cd)
power_max(enemy_all) = 0.40 · power_max(cd)
```

Коэффициенты берут в расчёт, что к середине боя в ряду 1–2 живых:
множитель 0.4 держит `enemy_all` выгодной с трёх целей и убыточной с одной.
`planAction` считает так же: `score = power · 1.25 · min(живых, 3) · 0.8`.
Площадь без урона (`smoke_of_ples`, `borrowed_grief`, `inventory`) потолком
не ограничена, но обязана иметь `cooldown ≥ 3`.

Потолки 4.1–4.2 не нарушены ни одной способностью ростера.

### 4.3. Оглушение — не длиннее одного хода

Юнит тира 1 делает за бой 5–8 ходов; оглушение на 2 хода забрало бы
25–40 % его вклада за одно применение. Кроме того, статусы тикают в
`beginRound` **до** ходов, поэтому оглушение на 1 ход работает только
против тех, кто в очереди после оглушающего, — это делает его позиционным
и зависимым от инициативы носителя (честно и читаемо). Шероховатость
реализации — TODO п.3.

### 4.4. На первом ряду щит лучше лечения

`applyBattleEffect` тратит урон на щиты **до** hp; лечение упирается в
`maxHp`, приходит после проверки смерти и пропадает при полном hp. Передний
ряд получает 21–32 урона за раунд: одно лечение (~12 hp) отстаёт от потока
вдвое, щит гасит залп и срабатывает раньше, чем считается смерть. Задний
ряд — наоборот: урон копится медленно, лечение почти не пропадает.

## 5. Прогрессия

### 5.1. Опыт

```
xpForLevel(l) = 50 · l · (l + 1)        // порог перехода С уровня l НА l+1
```

`xp` в `PartyUnit` накопительный. Пороги: 100, 300, 600, 1000, 1500, 2100,
2800, 3600, 4500. Потолок — 10-й уровень.

### 5.2. Рост статов

`scaleStats`: `+12 %` hp и atk за уровень, `+8 %` def, инициатива **не
растёт** (иначе прокачанный отряд всегда ходил бы первым и правило строя
умерло бы). Линейно от базы. Уровень 10: hp/atk ×2.08, def ×1.72.
Def растёт медленнее из-за убывающей отдачи `K/(K+def)` (2.1).

### 5.3. Эволюция

`evolvesTo` + `evolveAt` (порог по накопленному `xp`). Опыт не
сбрасывается, уровень и `uid` сохраняются — меняются база статов и набор
способностей. Два порога на весь проект: **250** (уровни 2→3, тир 1→2) и
**700** (уровни 4→5, тир 2→3). Смена тира — смена рамки карточки;
это единственный визуальный маркер прогресса юнита, поэтому эволюций
всего пять цепочек на ростер:

| Цепочка | 250 | 700 |
|---|---|---|
| `hollow_sergeant` | → `debt_bailiff` | → `vault_lock` |
| `pocket_cutter` | → `guild_hoarder_vey` | → `memory_thief_orsa` |
| `brother_ash` | → `pale_deacon` | → `empty_head_elder` |
| `grateful_debtor` | → `almshouse_sister` | — |
| `ledger_clerk` | → `cold_reckoner` | — |

Первые три меняют и ряд, и роль — эволюция перестраивает строй.

## 6. Оси ↔ найм

`recruitable` — условие на юните (`recruitableUnits` в `progression.ts`).
Без `recruitable` — доступен всем; `{"kind":"never"}` — только враг.

### 6.1. Порог

Все наёмники стоят на **±40**, край мира — 60: игрок сначала получает
состав, потом видит крайние реакции. Форма условия всегда одна:

```json
{ "kind": "axis", "axis": "mercy_cruelty", "op": "lte", "value": -40 }
```

### 6.2. Кто приходит на каждый полюс

На каждый из восьми полюсов — три юнита: наёмники тир 1 и тир 2
(`faction: "companion"`) и перебежчик из близкой полюсу фракции
(перебежчики остаются и врагами).

| Полюс | Условие | Тир 1 | Тир 2 | Перебежчик |
|---|---|---|---|---|
| Милосердие | `mercy_cruelty gte 40` | `grateful_debtor` | `almshouse_sister` | `pale_deacon` |
| Жестокость | `mercy_cruelty lte -40` | `throat_taker` | `tar_burner` | `pocket_cutter` |
| Честность | `honesty_deceit gte 40` | `sworn_witness` | `plain_speaker` | `pawn_appraiser_dusk` |
| Обман | `honesty_deceit lte -40` | `promise_pedlar` | `borrowed_face` | `hook_man` |
| Рассудок | `reason_obsession gte 40` | `ledger_clerk` | `cold_reckoner` | `debt_bailiff` |
| Одержимость | `reason_obsession lte -40` | `archive_rat` | `flask_hoarder` | `guild_hoarder_vey` |
| Цепкость | `grasp_release gte 40` | `tight_fist` | `pledge_holder` | `memory_thief_orsa` |
| Отпускание | `grasp_release lte -40` | `barefoot_brother` | `gravedigger_of_things` | `brother_ash` |

### 6.3. Цена края

Край по оси наглухо закрывает противоположный полюс той же оси: **три
приходят, три уходят**, симметрия нарочная. Край не усиливает и не
ослабляет — меняет способ играть: милосердный отряд тянет бой (единственное
наёмное лечение по отряду), жестокий обязан кончить бой за ~5 раундов,
потому что чинить его нечем; уходящие тройки уносят уникальные инструменты
(единственное оглушение — у рассудка, единственный dot по стороне — у
одержимости, доступ к наёмному тиру 3 — у цепкости).

### 6.4. Вне системы осей

- **Отголоски** (`faction: "echo"`, тир 2) приходят закреплением
  воспоминаний, не наймом: `gar`, `vodonos`, `posul`, `svidetel`.
- **Стартовые союзники** главы 1 (`companion`, тир 1, без `recruitable`):
  `unclaimed_pledge` (передний, щит) и `dusty_errand_boy` (задний,
  стрелок). Двое нарочно: игрок сразу видит оба ряда и чувствует неполноту.

## 7. Смерть

Смерть — не проигрыш, а способ вернуть себе воспоминание.

### 7.1. Осколки

Эффект `{ "kind": "fragment", "memory": "…", "amount": N }` копит осколки;
воспоминание может закрепиться при `осколков ≥ cost`. Цены в контенте —
**2 / 3 / 4** внутри каждой жизни (3 воспоминания × 5 жизней). Калибровка:
вылазка (10–15 мин) даёт 2–4 осколка; смерть — раз в одну-две вылазки;
глава даёт 2–3 закрепления; 15 воспоминаний закрываются за три главы плюс
финал.

### 7.2. Какой лот выдаётся

`selectMemoryOnDeath` (`progression.ts`) среди готовых и незакреплённых
сортирует: (1) больше осколков; (2) при равенстве — тяга оси
`pull = pole === 'positive' ? axis : −axis`, побеждает полюс, ближний к
поведению игрока; (3) по `id` для воспроизводимости. Если готовых нет —
лот не выдаётся, смерть всё равно засчитывается.

### 7.3. Что делает `applyDeath`

1. Лот — в `lockedMemories` навсегда, применяются `memory.grants`.
2. Первое воспоминание своей жизни будит жизнь (`awakenedLives`,
   `life.grants` — обычно `recruit` отголоска); второе уже не будит.
3. Отряд восстанавливается: hp каждого — к базовому значению определения.
4. Сцена → `death.wakeScene`, узел `@entry`, лента очищается.

## 8. Балансовые коридоры

### 8.1. Три коридора

| Метрика | Коридор | Чем меряется |
|---|---|---|
| Винрейт юнита в зеркальном турнире | **42–58 %** | `unitWinrates`, `packages/sim` |
| Винрейт бота в сюжетном бою | **60–85 %** | `scriptedBattles` |
| Длина боя | **6–14 раундов** | `avgRounds` |

Бот играет хуже человека: 60–85 % у бота — «посильно, но не даром» у
игрока. Бой с тегом `lethal` коридору не подлежит. Метод зеркала — **замена
одного слота** в эталонном отряде тира: 50 % = «ровно настолько же полезен,
как вытесненный». Тир 3 (трое юнитов) зеркалом не меряется — только
сюжетными боями, метка `~~`.

### 8.2. Нулевая точка зеркала — не 50 %, а 52–56 %

Прогон зеркала само против себя даёт 55.3 % (тир 1) и 52.4 % (тир 2) в
пользу стороны «игрока». Причина в `combat.ts`: `rollIntents` планирует
врагов один раз в начале раунда, а сторона игрока зовёт `planAction` в
момент хода и переприцеливается по свежему состоянию. Следствия: средний
юнит тира 1 показывает ~55 %, коридор к этой точке несимметричен (запас
снизу 13 пунктов, сверху 3); «ослабить всех» не работает — среднее
самореферентно, работает только сжатие разброса. Рекомендация владельцу
движка: либо считать интенты в момент хода, либо задать коридор «нулевая
точка ± 8» вместо жёстких 42–58 %.

### 8.3. Точность прогона

При `--runs=120` σ ≈ 4.5 пункта — больше половины ширины коридора.
Балансовые решения — на **800+ прогонах**; на 120 сравнивать среднее и
разброс, не «сколько вне коридора».

### 8.4. `enemy_any` — налога нет, и почему

Проверено контрольным опытом: при равной силе `enemy_any` **хуже** ближней
цели (−3.8 п. на переднем ряду, −9.8 на заднем) — бот с `enemy_front`
концентрирует огонь и вскрывает задний ряд, `enemy_any` размазывает урон.
Надбавка `hook_shot` 1.2 против 1.0 — компенсация, не переплата. Побочное
число из того же опыта: **при одинаковых статах задний ряд стоит на 30–38
пунктов винрейта дороже переднего** — ради этого и существует разница
статов между рядами в 3.1.

### 8.5. Что бот умеет и чего не умеет (`planAction`)

Ограничения, которые нельзя обойти данными; критично для всех, кто трогает
бот-политику или способности:

- **Порог вместо плавности.** Бот берёт одну способность с максимальным
  `score`; шаг силы 0.1 может стоить десятки пунктов винрейта (способность
  либо выбирается всегда, либо никогда).
- **Плоские эффекты не масштабируются атакой:** `damage`/`heal` считаются
  от `atk`, `shield`/`dot`/`debuff`/`stun` — нет. Площадная порча у слабого
  носителя абсурдно выгодна — режется сама способность, не носитель.
- **Часть целей боту недоступна:** `ally_one`/`ally_all` достаются только
  веткой лекаря (союзник ниже 55 % hp). Весь щитовой инструментарий висит
  на `ally_one` (`i_will_hold_it`, `promise_note`, `burst_for_him`).
- Исключение ростера: у `stand_in_the_doorway` `power 1.2` — **вес
  приоритета**, не урон (иначе бот никогда не встаёт в дверях);
  единственная способность, где `power` ≠ урон. Носители — только тир 3.

## 9. Экономика

### 9.1. Две валюты

| | Что это | Где в коде |
|---|---|---|
| **Грош** | расписка на чужое воспоминание | `state.gold`, эффект `{"kind":"gold","delta":N}` |
| **Лот** | вынутое воспоминание, вещь | `fragments` / `lockedMemories` |

Гроши тратятся, лоты закрепляются; купить лот за гроши нельзя — иначе
смерть перестала бы быть единственным способом вернуть себя.

### 9.2. Прейскурант

Опора: совесть оценена «в четыре гроша» — грош мелкая единица, шкала от
четырёх.

| Позиция | Цена, грошей |
|---|---|
| Справка в архиве, мелкая услуга | 2–4 |
| Перевязка отряда между вылазками | 6 |
| Проход мимо стражи, взятка | 8–12 |
| Наём юнита тира 1 | 15–20 |
| Наём юнита тира 2 | 25–35 |
| Снятие выцветания, крупная услуга | 40–60 |

Доход за вылазку: **10–25 грошей** — наём тира 2 стоит две-три вылазки без
других трат; постоянный выбор «починиться сейчас / усилиться потом» — един-
ственное место, где мир прямо спрашивает про `grasp_release`.

Скидки и наценки по осям (числа осей игроку не показываются, он видит цену):

| Ось | Эффект на цены |
|---|---|
| Рассудок ≥ 40 | −25 % на услуги архива |
| Честность ≥ 40 | оплачиваемая работа свидетелем: +5–10 грошей за вылазку |
| Милосердие ≥ 60 | тарифы +20 % («доброта — признак платёжеспособности») |
| Обман ≤ −40 | одна покупка за вылазку бесплатно (посулы как валюта) |
| Одержимость ≤ −40 | наценка 15 % на всё, кроме архива |
