# Сценаристу: всё, что нужно, и ничего больше

Этот файл — единственная точка входа для работы над сюжетом. Прочитав его,
ты можешь писать сцены, не зная про движок ничего.

**Про код тебе знать не нужно, и трогать его нельзя.** Сцены — это данные:
JSON-файлы в `packages/content/data/scenes/`. Никакой TypeScript открывать не
надо; если кажется, что надо, — значит задача сформулирована плохо, спроси.

---

## 1. Что прочитать перед работой — четыре файла, не сорок

| Файл | Зачем |
|---|---|
| `docs/КАНОН_КРАТКО.md` | мир на одной странице: что здесь правда, чего не бывает |
| `docs/ЛЮДИ.md` | все люди по три-пять строк: кто, чем занят, чем говорит |
| `docs/STYLE.md` | тон: как здесь пишут и как здесь не пишут |
| `docs/ИМЕНА.md` | имена: как кого зовут сейчас (после переименования) |

Плюс шапка твоей задачи в `ЗАДАЧИ.md`. Всё. В `docs/` есть и другое, но оно
для программистов; читать его — тратить время.

## 2. Как увидеть свою сцену за пятнадцать секунд

Раньше единственным способом было доиграть до сцены с начала. Теперь:

```
# один раз за сеанс — поднять игру
pnpm --filter @nameless/client build
cd packages/client && npx vite preview --port 4173 --strictPort &

# дальше сколько угодно раз
node tools/scene.mjs hearth_reckoning
node tools/scene.mjs skhod golos_empty       # прыжок в конкретный узел
node tools/scene.mjs shcherb_road '' 360 640 # узкий экран
```

Скрипт начинает забег, подменяет в сейве место и прокручивает сцену до
первого выбора. Печатает последние реплики, варианты выбора, куда сцена
привела (диалог, бой, церемония смерти) и путь к снимку. **Снимок открывай
глазами** — половина находок этого проекта была видна только на картинке.

**После правки JSON нужна пересборка** — `vite preview` отдаёт готовый
`dist`, а не исходники. Цикл такой:

```
правка сцены → pnpm --filter @nameless/client build → node tools/scene.mjs <сцена>
```

Если правишь много и подряд, подними вместо этого `pnpm --filter
@nameless/client dev` (порт 5173) и укажи его скрипту:
`SCENE_URL=http://localhost:5173 node tools/scene.mjs <сцена>` — тогда
пересборка не нужна вовсе.

## 3. Из чего состоит сцена

Файл сцены — объект с полями `id`, `chapter`, `title`, `entry`, `nodes`.
`entry` — id узла, с которого сцена начинается. Дальше узлы ведут друг к другу
полем `next` или `to`.

**Переход** — это либо id узла в этой же сцене (`"svod_note"`), либо
`"scene:другая_сцена"`, либо `"scene:другая_сцена#узел"`.

### Девять видов узлов — больше не бывает

**`say` — кто-то говорит.**
```json
{ "kind": "say", "id": "svod_new", "speaker": "svodchik",
  "text": { "ru": "Такого в списке нет.", "en": "No such name on the list." },
  "next": "name_gap" }
```
`speaker` — id из `docs/ЛЮДИ.md`. `narrator` — рассказчик, у него нет лица.

**`narration` — говорит мир.** То же, но без `speaker`.

**`lore` — раскрывашка «рассмотреть ближе».** Плюс поле `title`. Сюда идёт то,
что игрок читает по своей воле: устав, вырезка, надпись. Не клади сюда то,
без чего сцена непонятна.

**`choice` — выбор.** Единственный узел без `next`: ведут сами варианты.
```json
{ "kind": "choice", "id": "hail_choice",
  "prompt": { "ru": "Имени нет.", "en": "There is no name." },
  "options": [
    { "id": "answer_none", "text": { "ru": "Сказать, что имени нет.", "en": "Say there is none." },
      "effects": [{ "kind": "axis", "axis": "honesty_deceit", "delta": 8 }],
      "fallback": true, "to": "dratva_no_name" }
  ] }
```

**`effects` — тихо поменять состояние.** Игрок ничего не видит.
```json
{ "kind": "effects", "id": "intake_out",
  "effects": [{ "kind": "counter", "counter": "hub_visits", "delta": 1 }],
  "next": "scene:shcherb_road" }
```

**`branch` — невидимая развилка.** Первая подошедшая ветка выигрывает;
`fallback` обязателен — это ответ на «а если ни одна».
```json
{ "kind": "branch", "id": "wake_router",
  "branches": [{ "when": { "kind": "deaths", "op": "gte", "value": 1 }, "to": "wake_again" }],
  "fallback": "wake_dust" }
```

**`battle` — драка.** `battle` — id боя, `onWin` и `onLose` — куда после.

**`death` — смерть игрока.** `death` — id смерти. Закрепляет воспоминание и
уводит на церемонию; это не «конец», а поворот.

**`end` — конец сцены без продолжения.** Нужен редко.

## 4. Условия: кому показывать

Ставятся в `conditions` варианта выбора и в `when` ветки. Шестнадцать видов:

| Вид | Что спрашивает | Пример |
|---|---|---|
| `always` / `never` | всегда / никогда | `{ "kind": "always" }` |
| `all` / `any` / `not` | и / или / не | `{ "kind": "not", "of": {…} }` |
| `axis` | значение скрытой оси | `{ "kind": "axis", "axis": "mercy_cruelty", "op": "lte", "value": -40 }` |
| `flag` | флаг мира | `{ "kind": "flag", "flag": "oklik_refused" }` |
| `counter` | счётчик | `{ "kind": "counter", "counter": "_shards", "op": "lt", "value": 2 }` |
| `memory` | воспоминание закреплено | `{ "kind": "memory", "memory": "pervaya_stroka" }` |
| `fragments` | сколько осколков набрано | `{ "kind": "fragments", "memory": "…", "op": "gte", "value": 2 }` |
| `life` | прошлая жизнь пробуждена | `{ "kind": "life", "life": "klyuchar" }` |
| `visited` | сцена уже была | `{ "kind": "visited", "scene": "skhod" }` |
| `deaths` | сколько раз умирал | `{ "kind": "deaths", "op": "gte", "value": 1 }` |
| `chapter` | какая глава | `{ "kind": "chapter", "op": "gte", "value": 2 }` |
| `hasUnit` | юнит в отряде | `{ "kind": "hasUnit", "unit": "vodonos" }` |
| `partySize` | размер отряда | `{ "kind": "partySize", "op": "lt", "value": 3 }` |

Сравнения: `gte` `lte` `gt` `lt` `eq` `neq`.

## 5. Эффекты: что сцена меняет

Десять видов, в `effects` варианта или узла `effects`:

| Вид | Что делает |
|---|---|
| `axis` | двигает скрытую ось: `{ "kind": "axis", "axis": "…", "delta": 8 }` |
| `flag` | ставит флаг: `{ "kind": "flag", "flag": "…", "value": true }` |
| `counter` | считает: `{ "kind": "counter", "counter": "…", "delta": 1 }` |
| `fragment` | осколок воспоминания: `{ "kind": "fragment", "memory": "…", "amount": 1 }` |
| `awakenLife` | пробудить прошлую жизнь — редко, только по сюжету |
| `recruit` / `dismiss` | спутник приходит / уходит |
| `heal` | лечит |
| `gold` / `xp` | деньги / опыт |

## 6. Железные правила. Их проверяет машина

1. **В любом выборе игроку всегда доступно минимум два варианта — при
   ЛЮБОМ состоянии.** Не «обычно два», а всегда. Поэтому у вариантов есть
   `"fallback": true` — такой не отфильтруется никогда. Держи в каждом выборе
   минимум два безусловных или `fallback`. Фаззер гоняет тысячи выдуманных
   игроков и краснеет, если хоть одному досталось меньше двух.
2. **≤10 слов на кнопке выбора.** Это правило большого пальца, не вкус.
3. **≤220 знаков в строке Помянника.**
4. **Не больше четырёх вариантов на экране.** Если написал больше — лишние
   отсекутся по `priority`, и кто-то из них не покажется никому.
5. **Числа скрытых осей игроку не показываются никогда.** Ни в тексте, ни в
   намёке «твоя жестокость выросла». Ось видна только последствиями.
6. **Вариант, который не увидит ни один игрок, — это мёртвый текст.** Прибор
   его находит и называет.

## 7. Проверка: две команды

```
pnpm validate     # схема и правила: длина кнопок, ссылки, дубли id
pnpm sim          # фаззер: тупики, недостижимое, мёртвые варианты, темп
```

`pnpm validate` — быстрая, гоняй после каждой сцены. `pnpm sim` — долгая,
гоняй перед сдачей задачи.

Ошибки на русском и говорят, что чинить. Если прибор ругается непонятно —
это дефект прибора, скажи, а не обходи.

**Известное красное** записано в `sim-baseline.json`. Новое красное сверх
базы — стоп, а не «оно и раньше падало».

---

## 8. Когда сцена готова

- `pnpm validate` чистый;
- `node tools/scene.mjs <сцена>` показывает то, что ты хотел, и снимок
  посмотрен глазами;
- в выборе минимум два варианта при любом состоянии;
- есть строка «о чём это по-человечески» — одно предложение, которое
  объясняет сцену, **не используя ни одного слова этого мира**. Не
  формулируется — сцена не готова: значит, она про термины, а не про людей.
  Это прямое требование владельца: «сделать так, чтобы было близко любому».

## 9. Граница работы

**Твоё:** `packages/content/data/scenes/**`, `packages/content/data/codex/**`,
`packages/content/data/speakers/**`, тексты в `docs/`.

**Не твоё:** всё в `packages/engine`, `packages/client`, `packages/sim`,
`packages/content/src`. Если сцене нужен вид узла, условия или эффекта,
которого нет в этом файле, — **не выдумывай его**: заведи вопрос в отчёте,
это работа программиста.
