# cards/ — свои портреты юнитов

Эта папка — для твоих собственных артов. Игра по умолчанию рисует портрет
юнита процедурно (силуэт-заглушка, см. `../procedural/procedural.ts`), но
если сюда положить файл с правильным именем — клиент **автоматически**
подхватит его вместо процедурной заглушки. Ничего в коде менять не нужно.

## Как назвать файл

Имя файла = **id юнита**, без префиксов и без заглавных букв:

```
gar.webp
vodonos.png
posul.webp
svidetel.webp
```

Известные на сегодня id отголосков (заднего ряда, «памяти» — прошлых
закреплённых жизней): `gar`, `vodonos`, `posul`, `svidetel`. Список id живых
попутчиков и врагов растёт вместе с контентом — смотри актуальные id в
`packages/content/data/units/` (там, где их размещают другие агенты); имя
файла портрета всегда повторяет id юнита из его JSON-файла.

## Формат

- **Соотношение сторон 3:4** (портретная ориентация — как игральная карта),
  например 600×800 или 900×1200 px. Любой другой формат исказится/обрежется
  под 3:4 при показе.
- **webp** предпочтительно (меньше вес при том же качестве), **png**
  тоже поддерживается. Без анимации (не gif/apng).
- Держи файл компактным — ориентируйся на ≤300 КБ на портрет, этого более
  чем достаточно для мобильного экрана.
- Фон может быть любым — рамка тира (1/2/3) накладывается поверх
  автоматически, как и для процедурных портретов, так что не обязательно
  оставлять поля под рамку.

## Что произойдёт

Если файл `<id>.webp` (или `.png`) есть в этой папке — клиент показывает его.
Если файла нет — клиент рисует процедурный силуэт через `unitCardSvg(id, tier,
faction)` из `procedural.ts`, детерминированно и без сети. Можно постепенно
подменять юнитов: часть с артами, часть ещё на процедурной заглушке — игра
не ломается ни в каком сочетании.
